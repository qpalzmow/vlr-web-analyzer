# VLR Web Analyzer

FastAPI, SQLite 및 일반 JavaScript로 구성된 VLR 경기 분석기입니다.

## 실행

```powershell
python -m pip install -r requirements.txt
python server.py
```

기본 포트는 7860이며 PORT 환경변수로 변경할 수 있습니다.

## 1시간마다 준비하는 경기 목록

- 경기 선택 → 대회 필터 선택 → 전력 분석 버튼 순으로 사용합니다. 공유 링크는 저장된 필터로 자동 분석합니다.
- 서버가 경기 일정, 확정된 팀 ID, 양 팀의 대회 목록, 맵 풀을 1시간 간격으로 수집합니다. 팀과 대회별 중복 요청은 한 번으로 합칩니다.
- 수집이 끝나면 전체 목록을 SQLite에 한 번에 교체합니다. 갱신 중에는 이전 목록을 계속 제공하고, 실패했다고 목록을 비우거나 클릭 시 외부 사이트를 조회하지 않습니다.
- 화면은 `/api/catalog`에서 완성된 목록을 받아 저장합니다. 경기 선택은 브라우저 안에서 즉시 처리하며 상세 정보·대회 목록·맵 풀·점수를 요청하지 않습니다. 기존 상세 API도 저장된 목록만 읽습니다.
- 화면은 1분마다 새로 게시된 목록이 있는지만 확인합니다. 서버 수집 주기는 1시간이며, 진행 중인 분석과 선택한 필터는 유지됩니다. 상단에 데이터 기준 시각을 표시합니다.
- 대진이 확정되지 않은 경기는 `대진 미정`, 수집되지 않은 경기는 `업데이트 대기`로 표시합니다. 이전에 준비된 동일 대진은 수집 실패 시 이전 데이터를 사용합니다.
- `data/catalog_seed.json`은 실제 수집한 공개 경기 데이터입니다. 처음 배포할 때 초기 목록으로 사용하며, 기존 SQLite 데이터가 있으면 그것을 우선 사용합니다. 이후 목록은 서버가 자동 갱신합니다.

## 한 번에 표시하는 전력 분석

- 서버는 1시간마다 경기 목록에 있는 팀의 전체 기간 통계와 선택 가능한 대회별 통계를 미리 수집합니다. 같은 대회의 선수 순위표는 여러 팀이 공유해 중복 수집을 줄입니다.
- 전력 분석 버튼은 `/api/analyze` 한 번으로 최근 흐름, 맵 전적, 에이스, 고급 지표, 승률과 밴픽 결과를 받아 함께 표시합니다. 이 요청에서는 VLR을 조회하지 않습니다.
- 대회를 선택하지 않으면 전체 기간의 팀 맵 전적과 현재 등록된 선수들의 커리어 통계를 사용합니다. 선수 페이지는 `timespan=all`로 수집합니다. 최근 흐름은 대회 필터와 별개로 최근 완료 경기 5개입니다.
- 대회는 양 팀의 최근 목록을 합쳐 최대 24개까지 선택할 수 있습니다. 선택한 대회의 승패·라운드·킬 등 원시 합계를 먼저 합산하고 승률과 평균 ACS를 계산합니다. 불참 대회에는 다른 기간의 통계를 대신 표시하지 않습니다.
- 에이스와 선수 지표는 현재 팀 페이지에 등록된 선수 기준입니다. 대회별 주력 요원은 공개된 요원 사용 비중에 라운드 수를 가중해 정렬한 참고 정보입니다. 원본에 선수 통계가 없는 대회는 에이스 및 선수 지표를 미표시하며, 불완전한 선수 통계로 승률을 만들지 않습니다.
- 수집에 실패한 범위는 마지막으로 성공한 값을 유지하고 기준 시각을 표시합니다. 아직 준비된 값이 전혀 없으면 409 응답과 준비 중 안내를 즉시 반환합니다.
- `data/analysis_seed.json`은 실제 수집한 공개 분석 데이터입니다. 새 배포도 첫 수집을 기다리지 않고 분석할 수 있도록 초기값으로 사용하며, 이미 저장된 팀 데이터는 보존합니다.
- 경기 점수는 분석 결과를 표시한 뒤 별도로 조회합니다. LIVE 25초, UPCOMING 60초 간격으로 갱신하며 FINAL이면 중지합니다.

## 자동 동기화 및 수동 관리

`app/catalog.py`의 전용 작업이 수집 시작 시각 기준 1시간 간격으로 갱신합니다. 팀 통계 예열은 별도 작업이라 경기 목록 갱신을 막지 않습니다. SQLite의 5분 임대 잠금을 1분마다 갱신해 중복 수집을 막으며, 중단된 작업은 임대 만료 후 복구합니다. 전체 수집 실패 시 이전 목록을 유지하고 5분 뒤 재시도합니다.

주기 작업은 서버 프로세스가 실행되는 동안 동작합니다. 호스팅에서 서버를 절전·중지하면 재시작 시 밀린 갱신을 실행합니다. 계속 정시 수집하려면 서버가 계속 실행되어야 합니다. 영구 디스크를 사용한다면 `VLR_DATA_DIR`을 그 디스크의 경로로 지정해 재배포 후에도 최신 목록을 보존할 수 있습니다.

`POST /api/sync/trigger` 및 `POST /api/cache/warm`은 기본적으로 비활성화(503)되어 있습니다. 수동 실행이 필요하면 서버의 VLR_MAINTENANCE_TOKEN 환경변수에 별도의 비밀값을 설정하고, 요청의 Authorization 헤더에 `Bearer <설정한 값>`을 전달합니다. 토큰을 화면 JavaScript에 넣지 마세요. 인증 실패는 401, 이미 실행 중이면 409, 직전 수동 실행 시작 후 5분이 지나지 않았으면 429를 반환합니다. 이 설정은 자동 동기화에 영향을 주지 않습니다.

## 테스트

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --test tests/frontend.test.cjs
```

Python 테스트는 임시 SQLite DB와 대체 수집 함수를 사용합니다. 프런트엔드 테스트는 Node의 내장 테스트 도구와 DOM 대체 객체로 경기 선택, 필터, 공유 링크, 점수 갱신, 차트를 검증합니다. 실제 VLR 연동, 실제 브라우저, Docker 실행 검증과는 구분됩니다.

## 자동 푸시 스크립트

auto_push.ps1은 60초마다 변경을 커밋하고 origin/master로 푸시합니다. 사용자 요청에 따라 자동 푸시를 유지합니다. 큰 변경은 별도 작업 디렉터리에서 검증한 뒤 원본 프로젝트에 반영합니다.
